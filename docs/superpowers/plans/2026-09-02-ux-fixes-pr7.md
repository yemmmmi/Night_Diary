# PR7 计划：四项 UX 修复 — 下拉遮挡 / 今天融入记录 / 时区 bug / 笔谈输入区

## 背景

用户在 PR6 合并后实测反馈四个问题（截图三张）：

1. 笔谈页「日常」模式下拉面板被左侧会话栏遮挡
2. 「今天」与「记录」的日视图重复，要求融合并去掉「今天」模块
3. 聊天消息时间显示错误（本地 9月2日，消息显示 9月1日）
4. 笔谈回信输入区从下划线改为圆角方框；「附上日记」需支持纯文本日记+卡片日记两类；新增「附上计划」

## 根因诊断

### 任务1 遮挡
ModeBadge 面板 `right: 0` 从徽标右缘向左展开 16rem，超出 `.chat-scene__main`（overflow: hidden）左边界被裁剪，视觉上被会话栏盖住。

### 任务3 时区（同 #105 同类 bug 的前端面）
后端 `datetime.utcnow()` 存 naive UTC，Pydantic 序列化无 Z 后缀：
- `ChatScene` 分日线 `created_at.slice(0,10)` 直接取 UTC 日期（北京 0-8 点差一天）
- `LetterMessage`/`TodayScene` 的 `new Date(naive)` 按本地解析（时间差 8 小时）
- 同类受害点：DayView/WeekView 卡片按日分组、CardsSection 显示、DiaryReferencePicker/DetailPanel 回退日期、DiaryScene 写日记默认日期

## 方案

### Task A 时区（前端统一解析层）
新建 `src/shared/utils/timeFormat.ts`：
- `parseServerTime(iso)`: 无时区后缀则补 'Z' 再解析
- `serverDateIso(iso)`: 服务器时间的本地 YYYY-MM-DD
- `serverTimeLabel(iso)`: 本地 HH:mm

替换全部消费点（见根因清单）。DiaryScene 默认日期改 `toIsoDate(new Date())`（本地）。后端不动。

### Task B 遮挡
ModeBadge 面板 `right: 0` → `left: 0`，向右展开落在主区内。

### Task C 融合今天与记录
- 从 TodayScene 抽出右栏为 `features/timeline/TodayRail.vue`（今日待办+快速添加+实际值表单 / 进行中的计划+进度条+拉一条），带响应式（窄屏下移）
- DayView 头部换大日期（chineseDateLabel + todaySubtitle，chineseDateLabel 所有日期适用）
- DayView 集成 TodayRail（仅 isToday 时显示），删除 TaskFoldRow（功能被 rail 完全覆盖）
- 路由：`/`(home) → TimelineScene；删 TodayScene 路由；NavTabs 删「今天」tab，「记录」指向 `/`
- App.vue keep-alive 列表去掉 TodayScene
- 删 TodayScene.vue + spec；TodayRail.spec.ts 从 TodayScene.spec.ts 迁移待办/计划部分；redirects/NavTabs spec 更新

### Task D 笔谈输入区
前端：
- ChatInput：底线式 → 圆角方框（1px 边框 + --radius-inner，focus 边框 accent）
- DiaryReferencePicker：列表分区「日记」（条目）与「卡片」（diary_id==null 独立卡）；选中卡片存 pinnedCardIds
- 新建 PlanReferencePicker（active 计划列表，pinnedPlanIds）
- chat store: pinnedCardIds/pinnedPlanIds，send payload 带 card_ids/plan_ids
- LetterMessage 参考注脚显示三类计数（回信侧「参考日记」保留；我的信侧新增「附上卡片/计划」虚线注脚）

后端：
- ChatMessageRow + additive_columns：attached_card_ids / attached_plan_ids（TEXT JSON，命名随请求字段 card_ids/plan_ids，与 retrieved_* 区分用户附上与 AI 检索两类语义）
- SendMessageRequest: card_ids/plan_ids（各 max 3 校验）
- conversation_ai_service: `_format_attached_cards` / `_format_attached_plans` 经 `_compose_pinned_context` 拼入 pinned 上下文（sync 与 streaming 两条路径）
- MessageResponse/mapper/service 落库回读
