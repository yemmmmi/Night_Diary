# 日记/周记/回顾合并重构 + 计划板块入列设计

> 日期：2026-08-25
> 状态：已获项目所有者批准（经可视化原型迭代确认）
> 范围：前端信息架构重组为主，后端小幅配合（API 参数与结构化字段）
> 参考原型：`.superpowers/brainstorm/session-20260825-merge/content/`（本地未入库）

## 1. 背景与问题

### 1.1 现状

前端导航 6 个入口中，「日记」「周记」「回顾」三个板块本质都在做同一件事——回看自己的记录，只是时间尺度不同（本周·天 / 本周·周 / 月→年）。项目所有者确认了四个结构问题（全部命中）：

- **A 时间尺度被入口切裂**：首页看板只显示本周，翻上周要去「回顾」的月历/时间线找；「周记」与首页看板无联动
- **B 周记是死胡同页面**：只有一封 AI 生成的信，无心情曲线（后端有 `avg_mood` 未展示）、不能跳回该周日记、无环比
- **C 回顾页承载过重**：月历 + 时间线 + 卡片 + 详情面板四合一，月历与时间线信息重叠
- **D 写作入口与浏览混杂**：首页既是本周看板又是写作入口，角色模糊

### 1.2 V3 战略约束（关键输入）

V3 定位为「记录 + 规划双轮驱动的个人生活助手」，闭环（记录→理解→规划→执行→反馈→复盘）是核心差异化。代码实况：

- 后端闭环已全部打通：计划 API、PlannerAgent、`source_refs` 引用日记原文、任务回写记忆、周报已拼「本周计划执行」段落
- 前端有四个断点：PlanScene 存在但不在导航（孤儿路由 `/plan`）、`source_refs` 未渲染、周报计划对比是纯文本、任务与日记永不同屏

**本次重构的真正机会：让闭环被看见。**

## 2. 目标与非目标

### 目标

1. 日记/周记/回顾合并为一个「日记」板块（统一时间轴，日/周/月三级缩放）
2. 周记从死胡同变为周视图内的活动卡片（心情曲线 + 计划 vs 实际可交互）
3. 计划板块（PlanScene）升为一级导航入口，渲染 `source_refs` 溯源
4. 回顾页的卡片浏览并入记忆库板块，月历/时间线并入时间轴
5. 全局执行"减法纪律"：砍压力点，让日记的温和气质统一全局

### 非目标

- 不改日记/卡片/周报的核心数据模型（仅加字段与查询参数）
- 不做年视图（YAGNI，月历翻页已够用）
- 不改会话/记忆库/模型板块的内部逻辑（记忆库仅吸收卡片浏览视图）
- 不新增推送/提醒类功能

## 3. 设计原则（第一性推导）

### 3.1 冲突时，日记赢

不对称依赖：规划的原材料是真实的记录，真实记录的前提是无评判空间。计划污染日记土壤（写日记时想着"AI 会拿这个建议我"）→ 记录自我修饰 → 飞轮原料劣化。**规划依赖记录，记录不依赖规划。**

### 3.2 温和是计划的增效剂

催促带来启动，接纳带来持续；内疚驱动的行为改变快速衰减，身份驱动的才持续。日记塑造身份（"我是会记录、会反思的人"），计划是身份的延伸。V3 后端已内置此哲学（prompt 禁施压措辞、UI 弱化逾期），前端跟上。

### 3.3 减法减的是压力点，不是功能

产品向用户索取的时刻压到最少：无导航红点、无逾期红色警告（过期任务是中性事实）、无"你已 N 天未写"、写作面零任务、空任务行整体隐藏。

### 3.4 温度分区与三座桥

- **写作面**（`/write/:id`）：绝对温和区，零任务出现
- **计划场景**（`/plan`）：积极区，但无任何催促元素
- **周信**：唯一允许两个世界全量交汇处，用观察框架而非考核框架——"计划了 6 件完成 2 件"是事实陈述，配合从日记找原因；用日记解释计划，不用计划审判日记

两个世界之间仅三座桥，均由用户掌门：

1. 日记 → 计划：AI 提案 + 用户确认（已存在，AI 零写权）
2. 计划 → 日记：`source_refs` 溯源渲染（读方向，不产生压力）
3. 双向 → 周信：观察式复盘

## 4. 信息架构

### 4.1 导航：6 → 5

| 之前 | 之后 |
|------|------|
| 日记 · 周记 · 记忆库 · 回顾 · 会话 · 模型 | **日记 · 计划 · 记忆库 · 会话 · 模型** |

「周记」「回顾」入口移除（并入时间轴）；「计划」从孤儿路由升为一级入口；「记忆库」吸收卡片浏览。

### 4.2 路由变化

| 路由 | 变化 |
|------|------|
| `/` | 重构为统一时间轴，子视图 `?view=day\|week\|month&date=YYYY-MM-DD`，默认 day |
| `/write`、`/write/:id` | 保留，绝对温和区（写作面零任务） |
| `/plan` | 保留，加入导航 |
| `/weekly` | 移除，redirect → `/?view=week` |
| `/review` | 移除，redirect → `/?view=month` |
| `/review/:diaryId` | 移除，redirect → `/write/:id` |

### 4.3 板块职责

| 板块 | 职责 | 时间尺度 |
|------|------|----------|
| 日记 | 记录轮的浏览与写作入口：统一时间轴 | 日 / 周 / 月，连续翻页 |
| 计划 | 规划轮的管理：今日待办、计划卡、溯源、AI 提案确认 | 今日 + 活跃计划 |
| 记忆库 | 记忆资产：画像、情景记忆、情绪图表、**卡片浏览与搜索** | 全量 |
| 会话 | 对话 + AI 提案发起（不变） | — |

## 5. 日记板块：统一时间轴

### 5.1 日视图（默认落地，写作优先）

```
┌─ 顶部：视图切换（日/周/月） + 「＋记一笔」常驻右上角 ─┐
│
│ [今天的日记卡]  日期 · 天气 · 内容预览 · [继续写] · 自动保存状态
│ [任务折叠行]    "☑ 今日 3 项 · 已完成 1"（点击展开，可勾选）
│ [今日记忆卡片]  如有，附于日记卡下方
└──────────────────────────────────────────┘
```

- 写作优先：首屏第一元素是今天的日记（已有内容显示预览 + 继续写；无内容显示记一笔引导）
- 任务折叠行为中性摘要，点开展开为可勾选列表；**无任务时整行隐藏**
- 点击日记卡 → 右侧详情面板（浏览态）；「继续写」→ `/write/:id`（编辑态）

### 5.2 周视图（周信激活的地方）

结构（自上而下）：

1. 周导航：`‹ 前一周 | 8月25日 – 8月31日 · 第35周 | 后一周 ›`（可无限向前翻，解决诊断 A）
2. 本周概览行：心情曲线（ECharts mini 条形/折线，数据源 `mood-trends`）+ 统计（日记 N 篇 · 卡片 M 张 · 任务 done/total）
3. 7 天列（沿用现有周看板的列布局，迁移 HomeScene 逻辑）：每日展示日记条目与记忆卡片，今日列高亮
4. 周信卡片（嵌入）：
   - 未生成 → 「生成本周周信」按钮
   - 生成中 → `AITypingIndicator` 流式指示
   - 已生成 → 预览 + 展开全文 + 重新生成；内含「本周计划执行」结构化区块（见 5.5）

### 5.3 月视图（快速跳转）

- 月历网格：有日记的日期底部小圆点，今日高亮（沿用 CalendarView 改造）
- `‹ 2026年8月 ›` 翻月；点击日期 → 跳转该日（日视图）或该周（周视图）
- 无年视图（YAGNI）

### 5.4 详情面板（浏览态）

- 点击时间轴上任意日记卡，右侧滑出详情面板（桌面 `1fr min(20rem, 34%)` 布局，沿用回顾页面板逻辑迁移）
- 内容：日期、天气、关联卡片情绪/类型、日记摘要、状态标签、AI 回信预览
- 操作：继续编辑（→ `/write/:id`）、查看回信、导出 Markdown、删除（带确认）
- 移动端：面板全屏覆盖

### 5.5 周信卡片：计划 vs 实际（结构化）

现状问题：`weekly_service._build_weekly_content` 把计划执行拼成纯文本。改造：

- 后端 `WeeklyReportResponse` 新增可选结构化字段：

```python
class PlanExecutionSummary(BaseModel):
    plan_id: str
    title: str
    done: int
    total: int

class WeekTaskItem(BaseModel):
    task_id: str
    title: str
    status: str  # pending | done | skipped
    source: str  # manual | agent
    due_date: datetime.date | None

class WeeklyReportResponse(BaseModel):
    # ...现有字段不变...
    plan_executions: list[PlanExecutionSummary] = []   # 计划内汇总
    week_tasks: list[WeekTaskItem] = []                # 独立任务明细
```

- 前端渲染：计划汇总行（「换工作准备 2/5」）+ 任务行（勾选框可交互 + AI 建议任务带溯源链接「来自 8/12 日记 ↗」）
- 勾选直接调 `PATCH /api/v1/tasks/:id`，与计划场景共享 planStore 状态
- 兼容：字段为可选，旧周报（无结构化数据）回退渲染 `content` 纯文本

## 6. 计划板块：独立场景（积极但不催促）

基于现有 PlanScene 升级：

1. **加入导航**（`PhMapTrifold` 或同类图标，label「计划」）
2. **今日待办**：完整勾选列表（现状保留）；过期任务中性灰显示，无红色/警告
3. **计划卡**：
   - 标题 + `source: agent` 时显示「AI 建议」badge（现状保留）
   - 进度 `done/total`（现状保留）
   - **新增：`source_refs` 溯源渲染**——引用块样式展示「来自你的日记：最近三周 5 次提到失眠与换工作的犹豫（8/12 · 8/15 · 8/19 ↗）」，点击日期跳转 `/write/:id` 对应日记
   - 任务列表可勾选（现状保留）
4. AI 提案确认入口沿用会话场景的 PlanProposalCard（不在本板块重复）

## 7. 记忆库板块：吸收卡片浏览

- 回顾页 `mode=cards` 视图（卡片列表 + 搜索 + 展开为日记 + 删除）整体迁移至 MemoryScene 新增「记忆卡片」分区
- MemoryScene 现有的 `goToCards()` 跳转链接改为本板块内锚点/子视图
- 无日记绑定的卡片保留「展开为日记」操作

## 8. 数据与 API 变化

| 接口 | 变化 | 说明 |
|------|------|------|
| `GET /api/v1/diary/entries` | 新增可选 `date_from`、`date_to` 查询参数 | 周/月视图按范围拉取，替代全量分页拉取后前端过滤 |
| `GET /api/v1/weekly` 及 latest | 响应新增 `plan_executions`、`week_tasks` 可选字段 | 见 5.5；生成侧 `weekly_service` 填充 |
| `GET /api/v1/plans` + `GET /api/v1/tasks` | 周视图任务来源；若现有接口不支持日期过滤，实现时选择加参数或前端过滤 | 择一，倾向加 `date_from/date_to` 保持一致性 |
| `GET /api/v1/cards/stats/mood-trends` | 无变化 | 周视图心情曲线数据源 |
| `POST/PATCH /api/v1/tasks/:id` | 无变化 | 周信/时间轴/计划三处勾选共用 |

## 9. 错误处理与空态

| 场景 | 处理 |
|------|------|
| 周视图无日记 | 空态文案 + 「记一笔」入口 |
| 周信未生成 | 「生成本周周信」按钮（沿用 WeeklyStore.generate） |
| 周信生成失败 | 沿用现有错误提示模式，可重试 |
| 日视图无任务 | 折叠行整体隐藏（不显示"无待办"） |
| 时间轴加载失败 | 视图级错误提示 + 重试 |
| 旧周报无结构化计划数据 | 回退渲染 content 纯文本（见 5.5） |

## 10. 测试策略

### 前端（vitest）

- 视图切换状态机：`?view=` 参数解析与同步、日期跳转
- 周信卡片三态：未生成 / 生成中 / 已生成（含结构化计划区块渲染与回退）

### 后端（pytest）

## 13. 决策记录

| 决策点 | 结论 | 依据 |
|--------|------|------|
| 合并路线 | 统一时间轴（方案 A） | 唯一正面解决全部四个诊断的路线 |
| 计划放置 | 混合：执行上时间轴（折叠摘要），管理独立场景 | 闭环可见性 vs 管理工作台特性 |
| 日视图任务强度 | 折叠摘要（中性一行，点开展开） | 写作优先 + 压力控制 + 可见性平衡 |
| 核心场景 | 写看并重 | 用户确认 |
| 改动边界 | 前后端都可动 | 用户确认 |
| 设计哲学 | 日记气质统一全局，砍压力点 | 第一性推导 + V3 后端既有哲学（禁施压、弱化逾期） |
