> **阶段**: P6（V3 路线图第六阶段）
> **工期**: 约 2.5 天
> **前置依赖**: P0-P5 已合并 + MySQL 切换完成

## 1. 目标

报告 P6 原定义"缓存+并行"四项，工期 1 周。本阶段先做低风险高回报的 3 项（预热 + LRU + 异步写入），用 P5 探针测出基线后再评估是否需要并行化。

1. **预热机制**——消除首次请求 3-8s 模型冷启动（BgeEmbedder + Reranker lazy load）
2. **LRU 会话缓存淘汰**——修复 `_sessions` 裸 dict 无上限的内存泄漏风险 + 加命中率指标
3. **记忆异步写入**——记忆持久化改 fire-and-forget，砍掉尾部 50-300ms 同步阻塞

**成功标准**:
- 首次请求不再含模型加载延迟（重启后首个请求 < 2s vs 当前 5-9s）
- `_sessions` 有上限淘汰 + 命中率可观测
- 记忆写入不阻塞请求响应
- `/dev/stats/performance` 的 bottleneck_spans 中 S7_memory/S10_memory 大幅下降

## 3. 架构设计

### 3.1 预热机制

**问题**：`_bootstrap_ai_sync` 是死代码（lifespan 未调它），embedder/reranker 完全靠首次请求的 `ensure_ai_stack()` → 下游首次 `embed()`/`predict()` 懒加载触发，冷启动 3-8s。

**方案**：

`container.py` 新增 `warmup_models()`:
```python
def warmup_models(self) -> None:
    """Preload embedding + reranker models (best-effort, non-blocking on failure)."""
    import time as _time
    t0 = _time.perf_counter()
    try:
        self.ensure_ai_stack()
        embedder = self._build_embedder()
        embedder.embed("预热")
        logger.info("Embedder warmed up in %.2fs", _time.perf_counter() - t0)
    except Exception as exc:
        logger.warning("Embedder warmup failed (non-fatal): %s", exc)
    try:
        reranker = self._get_reranker()
        if reranker is not None:
            # trigger CrossEncoder load with dummy data
            reranker.rerank_episodic("预热", [_dummy_entry()])
        logger.info("Reranker warmed up in %.2fs", _time.perf_counter() - t0)
    except Exception as exc:
        logger.warning("Reranker warmup failed (non-fatal): %s", exc)
```

`main.py` lifespan 接入后台预热:
```python
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    ...
    core_task = asyncio.create_task(asyncio.to_thread(_bootstrap_core_sync, app))
    # 后台预热模型（不阻塞 startup / 不阻塞 /ready）
    async def _warmup_after_core():
        await core_task  # 等 core 完成
        container = app.state.container
        if container is not None:
            await asyncio.to_thread(container.warmup_models)
    asyncio.create_task(_warmup_after_core())
    yield
    ...
```

### 3.2 LRU 会话缓存

`session_context.py`:
- `_sessions: dict` → `OrderedDict`
- 新增 `MAX_SESSIONS = 32`
- `get_or_create_session` 命中后 `move_to_end`
- 超限 `popitem(last=False)` 淘汰最久未访问
- 新增 `_hits / _misses` 计数器 + `get_session_cache_stats()` 返回 `{"hits", "misses", "size", "maxsize", "hit_rate"}`

### 3.3 记忆异步写入

复用 `app.infrastructure.task_queue.enqueue_task`（与 `schedule_entity_extraction` 一致）:

- `analysis_service._sync_diary_to_memory`：把 `gw.persist_atom(atom)` 改为 `enqueue_task(gw.persist_atom, atom)`
- `conversation_ai_service._maybe_persist_episodic`：同理
- trace span 标记 `STATUS_DISPATCHED`（记录"已调度"而非"已完成"）

## 4. 测试策略

| 测试 | 覆盖 |
|------|------|
| warmup 成功加载模型 | embedder/reranker 首次 embed/rerank 后 _model 不为 None |
| warmup 失败静默降级 | 模型不可用时只 warn 不 crash |
| LRU 淘汰正确 | 超 MAX_SESSIONS 后淘汰最久未访问 |
| LRU 命中率统计 | hit/miss 计数正确 |

| 记忆异步失败降级 | enqueue_task 内部异常只 warn |
